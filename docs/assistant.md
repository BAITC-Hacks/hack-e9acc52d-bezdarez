# AI-помощник

Помощник отвечает на свободные вопросы: объяснения, математика, программирование, тексты, переводы и продолжение разговора. Ответы генерирует языковая модель. Для вопросов о симуляторе он дополнительно получает текущие решения, бюджет, каталог проектов, синергии и рассчитанные результаты на 1 и 3 года.

Язык выбирается в настройках приложения: «Язык интерфейса» → Русский / Қазақша / English. Новые ответы помощника и AI-объяснения результатов запрашиваются на выбранном языке; прямую просьбу ответить на другом языке можно написать в сообщении. Подсказки, названия проектов, предлагаемые действия и системные объяснения также переведены. Уже сохранённые сообщения не переводятся автоматически: история остаётся в исходном виде и доступна после смены языка.

История из последних 40 сообщений сохраняется в браузере; модель получает до 16 последних сообщений, суммарно до 12 000 символов. «Новый диалог» очищает историю и отменяет текущий запрос. Enter отправляет вопрос, Shift+Enter добавляет строку. Поддержаны абзацы, списки и блоки кода. Ответ backend ожидается до 90 секунд при локальной конфигурации, браузер отменяет запрос через 125 секунд. Первый ответ после загрузки модели может потребовать больше времени.

Модель может предложить выбрать проект, изменить бюджет, распределить бюджет или составить полный план. Перед применением показываются изменения и расчёт движка. Решения меняются только по кнопке пользователя. Полный план проверяется: все пять сфер, известные проекты, бюджеты 5–40 и сумма 100. Если черновик изменился, старые предложения блокируются.

## Локальная модель в этом проекте

Переносимая локальная конфигурация использует `Qwen3.5-9B-Kazakh` от ISSAI, квантование Q4_K_M, через llama.cpp для Windows/Vulkan. Файл модели — `.local-ai/Qwen3.5-9B-Kazakh.Q4_K_M.gguf`; содержимое `.local-ai/` исключено из Git. Backend запускает модель с выгрузкой слоёв на видеокарту, если в корневом `.env` задано `LOCAL_AI_AUTOSTART=1`. При обычном завершении backend останавливает только собственный процесс модели; уже работающий сервер не завершает.

На новой Windows-машине после клонирования выполните из корня проекта в PowerShell:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
backend/.venv/Scripts/python.exe -c "import secrets; from dotenv import set_key; set_key('.env', 'LLM_API_KEY', secrets.token_urlsafe(32))"
```

Последняя команда один раз создаёт случайный локальный ключ и записывает его в `.env`, не выводя в терминал. При повторном выполнении ключ заменяется; после этого нужно перезапустить backend и его локальную модель. Backend передаёт тот же ключ модели через окружение. Облачная подписка не требуется, `.env` и содержимое `.local-ai/` не публикуются.

В `.env` сохраните сгенерированный `LLM_API_KEY` и замените значения остальных параметров следующими. Каждая переменная должна иметь только одно активное определение:

```dotenv
LLM_API_URL=http://127.0.0.1:8087/v1
LLM_MODEL=Qwen3.5-9B-Kazakh
LLM_TIMEOUT_SECONDS=90
LOCAL_AI_AUTOSTART=1
```

Затем из корня проекта загрузите модель и запустите backend:

```powershell
python scripts/setup_local_ai.py
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Установка модели — отдельный шаг с загрузкой примерно 5,7 ГБ. Скрипт проверяет SHA-256 и поддерживает продолжение загрузки. При обычном старте приложения загрузок нет: повторно нужна только команда `uvicorn`.

Во втором терминале из корня проекта выполните `cd frontend`, `npm.cmd ci`, затем `npm.cmd run dev`. Откройте `http://localhost:5173`. При последующих запусках `npm.cmd ci` повторять не требуется. Если порт 8000 занят, выберите свободный порт backend и задайте `VITE_PROXY_TARGET` перед запуском Vite, например `$env:VITE_PROXY_TARGET = 'http://127.0.0.1:8011'` для backend на порту 8011.

Параметры локального сервера: контекст 16 384 токена, один запрос одновременно, `batch-size=256` и `ubatch-size=128`. Режим рассуждений выключен через `--reasoning off` и `enable_thinking=false`. Готовность модели проверяется через `/api/health`; качество ответов на каждом языке проверяется отдельно на реальных запросах.

Модель и диалог работают на компьютере; [API карты 2ГИС](2gis.md) настраивается отдельно. Модель не получает доступ к интернет-поиску и не должна заявлять, что проверила свежие сведения.

Эта инструкция предназначена для нативного Windows-запуска. Docker Compose запускает Linux-контейнеры frontend и backend и не устанавливает переносимую Windows-модель. Адрес `127.0.0.1` внутри контейнера относится к этому контейнеру, поэтому приведённый выше адрес модели нельзя без изменений использовать в Docker. Для контейнерного backend требуется отдельно доступный AI API; для модели из комплекта используйте нативный запуск.

Исходники и лицензии: [модель ISSAI](https://huggingface.co/issai/Qwen3.5-9B-Kazakh), [GGUF-квантование mradermacher](https://huggingface.co/mradermacher/Qwen3.5-9B-Kazakh-GGUF), [llama.cpp b10964](https://github.com/ggml-org/llama.cpp/releases/tag/b10964). Ответы генерируются моделью и могут содержать ошибки.

## Другое подключение нейросети

Настройки находятся в корневом `.env`, читаются только backend. Скопируйте `.env.example` и заполните один вариант. Ключ 2ГИС используется отдельно для карты и не является ключом нейросети.

NVIDIA API:

```dotenv
LLM_API_KEY=<ключ NVIDIA>
LLM_API_URL=https://integrate.api.nvidia.com/v1
LLM_MODEL=meta/llama-3.3-70b-instruct
LLM_TIMEOUT_SECONDS=25
```

Локальный совместимый сервер, например уже установленная Ollama:

```dotenv
LLM_API_KEY=
LLM_API_URL=http://127.0.0.1:11434/v1
LLM_MODEL=<точное имя установленной модели>
LLM_TIMEOUT_SECONDS=25
```

При переключении на другой сервер установите `LOCAL_AI_AUTOSTART=0`. Модель должна поддерживать диалог и JSON-ответы. Можно добавить `NVIDIA_API_KEY` и необязательный `NVIDIA_MODEL` как резервный провайдер. После изменения `.env` перезапустите backend. `/api/health` проверяет готовность настроенной локальной модели, для облачных провайдеров доступность подтверждается первым успешным ответом.

Если AI недоступен, чат показывает ошибку и кнопку повтора, не заменяя ответ шаблоном. Отдельный блок «Подсказки по вашим решениям» по-прежнему работает без модели. Игровые действия проверяются по каталогу и ограничениям бюджета. Числа в обычной беседе не фильтруются по игровым показателям: математика, даты и код разрешены. Строгие проверки специального `/api/explain` сохранены.

## Проверка

```powershell
cd backend
.venv/Scripts/python.exe -m pytest -q
cd ../frontend
npm.cmd test
npm.cmd run build
```

Тесты API используют подставной ответ провайдера и не требуют оплачиваемых запросов. Проверка настоящей генерации требует запущенной локальной модели или действующего ключа нейросети.
